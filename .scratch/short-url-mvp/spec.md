# Spec: 단축 주소 서비스 첫 버전

Status: ready-for-agent

## Problem Statement

긴 URL은 메신저, 문서, 말로 전하기에 불편하다. 사용자는 회원가입이나 로그인 없이, 긴 URL을 사람이 읽고 말로 불러 줄 수 있을 만큼 짧은 주소로 바꾸고 싶다. 그 짧은 주소를 받은 사람은 클릭 한 번으로 원래 페이지에 도착해야 한다.

## Solution

웹 페이지 하나에서 Original URL을 넣고 Shorten하면 `서비스 주소/42` 같은 Short Link를 받는다. Link Number는 1부터 차례로 늘어나는 10진수다. 누구든 Short Link로 들어오면 서버가 Original URL로 Follow시킨다. 로그인, 수정, 삭제는 없고, 한번 만든 Short Link는 계속 남는다.

## User Stories

1. 방문자로서, 로그인 없이 첫 화면에서 바로 URL을 넣고 싶다. 가입하는 수고 없이 쓸 수 있도록.
2. 방문자로서, 입력칸 하나와 "줄이기" 버튼만 있는 화면을 보고 싶다. 무엇을 해야 할지 바로 알 수 있도록.
3. 방문자로서, Original URL을 넣고 줄이기를 누르면 Short Link를 받고 싶다. 짧은 주소를 다른 사람에게 전할 수 있도록.
4. 방문자로서, Short Link가 `서비스 주소/숫자` 형태이길 원한다. 사람이 읽고 말로 불러 줄 수 있도록.
5. 방문자로서, 결과 옆의 "복사" 버튼으로 Short Link를 클립보드에 복사하고 싶다. 직접 드래그해서 복사하지 않아도 되도록.
6. 방문자로서, 이미 누군가 줄인 Original URL을 다시 넣으면 같은 Short Link를 받고 싶다. 같은 페이지에 Short Link가 여러 개 생기지 않도록.
7. 방문자로서, 대소문자나 기본 포트만 다른 URL(`HTTPS://Example.COM:443/a`와 `https://example.com/a`)을 넣어도 같은 Short Link를 받고 싶다. 표기 차이 때문에 중복이 생기지 않도록.
8. 방문자로서, URL 앞뒤에 실수로 들어간 공백이 무시되길 원한다. 복사-붙여넣기 실수로 실패하지 않도록.
9. 방문자로서, 끝에 `/`가 있고 없는 URL은 서로 다른 URL로 취급되길 원한다. 실제로 다른 페이지일 수 있으니까.
10. 방문자로서, `http`나 `https`가 아닌 주소를 넣으면 이유가 담긴 오류 문구를 보고 싶다. 무엇이 잘못됐는지 알 수 있도록.
11. 방문자로서, URL 형식이 아닌 글을 넣으면 오류 문구를 보고 싶다. 오타를 고칠 수 있도록.
12. 방문자로서, 빈 칸으로 줄이기를 누르면 오류 문구를 보고 싶다. 아무 일도 일어나지 않는 것처럼 보이지 않도록.
13. 방문자로서, 2048자를 넘는 URL을 넣으면 길이 제한을 알려 주는 오류 문구를 보고 싶다.
14. 방문자로서, 이 서비스의 Short Link를 다시 줄이려 하면 거절당하고 싶다. 자기 자신을 가리키는 쓸모없는 링크가 생기지 않도록.
15. 방문자로서, 오류가 나도 입력한 내용이 그대로 남아 있길 원한다. 처음부터 다시 쓰지 않고 고칠 수 있도록.
16. 방문자로서, 줄이기를 한 번 더 하면 새 결과가 이전 결과를 대체하길 원한다. 여러 링크를 연달아 만들 수 있도록.
17. Short Link를 받은 사람으로서, Short Link를 열면 곧바로 Original URL로 이동하고 싶다.
18. Short Link를 받은 사람으로서, 발급된 적 없는 번호의 Short Link를 열면 "없는 링크"라는 404 페이지를 보고 싶다. 링크가 깨졌다는 걸 알 수 있도록.
19. Short Link를 받은 사람으로서, `/0`, `/007`, `/abc`처럼 올바른 Link Number가 아닌 주소를 열면 404 페이지를 보고 싶다.
20. Short Link를 받은 사람으로서, 404 페이지에서 첫 화면으로 돌아가는 링크를 보고 싶다. 직접 Short Link를 만들 수 있도록.
21. 운영자로서, 서비스 주소를 `BASE_URL` 환경 변수로 정하고 싶다. 배포 환경마다 Short Link 앞부분과 자기 주소 판단이 맞도록.
22. 운영자로서, `BASE_URL`이 없으면 `http://localhost:8080`을 쓰길 원한다. 로컬 개발을 설정 없이 시작할 수 있도록.
23. 운영자로서, 데이터가 SQLite 파일 하나에 저장되길 원한다. 서버를 재시작해도 Short Link가 유지되고 백업이 쉽도록.
24. 운영자로서, 서버를 처음 띄울 때 저장소가 자동으로 준비되길 원한다. 수동으로 테이블을 만들 필요가 없도록.
25. 운영자로서, 동시에 여러 사람이 줄이기를 해도 Link Number가 겹치거나 건너뛰는 순서 문제로 같은 번호가 두 번 발급되지 않길 원한다.
26. 운영자로서, 동시에 같은 Original URL을 줄여도 Short Link가 하나만 생기길 원한다.
27. 운영자로서, Follow가 302 리다이렉트로 이뤄지길 원한다. 나중에 클릭 수 집계 같은 기능을 붙일 여지를 남기도록.
28. 개발자로서, Shorten과 Follow 규칙을 화면과 분리된 모듈 하나에서 확인하고 싶다. 규칙을 빠르게 테스트하고 고칠 수 있도록.

## Implementation Decisions

- **구성**: Dioxus fullstack 앱 하나. 첫 화면(Dioxus 컴포넌트)과 Follow 리다이렉트, Shorten 서버 함수를 같은 서버 프로세스가 처리한다. 최신 안정판 Dioxus를 쓰며, 그에 맞게 Rust 툴체인을 올리고 Dioxus CLI를 설치한다.
- **Shortener 모듈** (깊은 모듈, 테스트의 주 경계): 화면, HTTP와 무관한 순수 Rust 모듈. 공개 인터페이스는 두 개뿐이다.
  - Shorten: 입력 문자열을 받아 Short Link를 돌려주거나, 거절 사유(빈 입력, URL 형식 아님, 허용되지 않는 스킴, 너무 김, 자기 주소)를 돌려준다.
  - Follow: 경로 조각(문자열)을 받아 Original URL을 돌려주거나 "없음"을 돌려준다. Link Number 해석(양의 10진수, 앞자리 0 없음)도 이 모듈이 맡는다.
  - 서비스 주소와 저장소 연결을 생성 시점에 주입받는다.
  - URL 검증, 정리, Link Number 발급, 중복 확인 규칙이 모두 이 안에 숨는다.
- **URL 정리 규칙**: 앞뒤 공백 제거, 스킴과 호스트 소문자화, 기본 포트(http `:80`, https `:443`) 제거. 경로, 쿼리, 프래그먼트, 끝의 `/`는 그대로 둔다. 정리한 형태로 저장하고 비교한다.
- **자기 주소 판단**: 정리한 Original URL의 호스트(포트 포함)가 서비스 주소의 호스트와 같으면 거절한다.
- **길이 제한**: 정리 전 입력 기준 2048자.
- **저장소**: SQLite 파일 하나. 테이블 하나에 Link Number(정수 기본키, 자동 증가)와 Original URL(유일 제약)을 둔다. 서버 시작 시 없으면 만든다. 파일 경로는 `DATABASE_PATH` 환경 변수, 기본값 `short-url.db`. 번호 발급은 `BEGIN IMMEDIATE` 트랜잭션 하나 안에서 Original URL 조회 → 없으면 `INSERT … ON CONFLICT DO NOTHING` → 다시 조회로 한다. 유일 제약에 걸려 실패한 AUTOINCREMENT INSERT도 번호를 써 버리므로, 충돌을 제약에만 맡기지 않고 먼저 조회해 번호가 건너뛰지 않게 한다. IMMEDIATE 트랜잭션이 같은 파일을 여는 다른 연결과도 한 번에 하나씩만 확인하고 넣게 한다. 저장소를 쓰거나 읽지 못하면 거절 사유가 아니라 저장소 오류로 따로 돌려준다(Shorten 서버 함수 503, Follow 503).
- **Link Number**: 1부터 시작해 하나씩 늘어나는 10진수 (ADR 0001).
- **Follow 응답**: 찾으면 302와 `Location: <Original URL>`. 찾지 못하거나 경로가 올바른 Link Number가 아니면 404 페이지.
- **라우팅**: `/`는 첫 화면, `/{경로 조각 하나}`는 Follow, 서버 함수와 앱 정적 자산은 각자 경로. 그 밖의 모든 주소(`/a/b`, `/1/` 등)는 404 페이지. Dioxus 화면 라우트와 서버 함수 경로가 Follow와 겹치지 않도록 한다.
- **설정**: `BASE_URL` 환경 변수, 기본값 `http://localhost:8080`. 끝의 `/`는 떼고 쓴다. 호스트가 있는 http(s) URL이 아니면 서버가 시작하지 않는다.
- **화면**: 입력칸, "줄이기" 버튼, 결과 영역(Short Link + "복사" 버튼), 오류 문구 영역. 거절 사유마다 한국어 문구를 보여 준다.

## Testing Decisions

- 좋은 테스트는 공개 인터페이스로 들어가 바깥에서 보이는 결과만 확인한다. 내부 함수, 테이블 구조, SQL은 테스트에서 직접 다루지 않는다. 저장소는 가짜로 바꾸지 않고 테스트마다 새 임시 SQLite를 쓴다.
- **경계 1: Shortener 모듈** (`cargo test`, 규칙 대부분): Shorten 결과와 거절 사유 하나하나, URL 정리와 동일 URL 판정, 번호가 1부터 차례로 발급됨, 서비스 주소가 Short Link에 붙음, Follow의 성공, 없는 번호, `0`, 앞자리 0, 숫자 아님, 아주 큰 숫자. 동시에 같은 URL을 Shorten해도 Short Link가 하나만 생기는지도 여기서 확인한다.
- **경계 2: HTTP 서버** (얇게): 임시 SQLite를 붙인 실제 서버에 요청을 보낸다. Shorten 서버 함수의 성공·거절 응답, `GET /{번호}`의 302와 `Location`, 없는 번호와 잘못된 경로의 404만 확인한다. 규칙은 경계 1에서 이미 확인하므로 다시 검사하지 않는다.
- 화면은 자동 테스트하지 않는다. `tests/home_page.rs`는 `/`의 서버 렌더링이 200과 서비스 이름을 돌려주는지만 보는 스모크 확인이며 화면 테스트가 아니다. 구현 후 직접 실행해서 줄이기, 복사, 오류 문구, 404 페이지를 확인한다.
- 기존 코드가 없어 참고할 선행 테스트는 없다. 이 두 경계의 첫 테스트가 이후의 기준이 된다.
- 진행은 `/tdd`를 따른다.

## Out of Scope

- 로그인, 사용자 계정
- Short Link 수정, 삭제, 만료
- 원하는 문자열로 Short Link 만들기(커스텀 별칭)
- 클릭 수 집계, 통계
- 최근 링크나 목록 화면
- 요청 속도 제한 등 남용 방지
- 배포 (로컬 실행까지만)
- 악성 URL 검사

## Further Notes

- Link Number를 차례로 발급하므로 누구나 다른 사람의 Short Link를 차례로 열어 볼 수 있다. 의도된 결과이며 ADR 0001에 기록돼 있다.
- 용어는 `GLOSSARY.md`를 따른다: Original URL, Link Number, Short Link, Shorten, Follow.
- 배포를 정할 때 요청 속도 제한과 남용 방지를 함께 정한다.
