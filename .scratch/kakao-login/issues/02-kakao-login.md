# 02: 카카오 로그인, 로그아웃, 로그인 화면

**What to build:** 로그인하지 않은 사람이 `/`에 오면 가운데에 사이트 이름과 "카카오 로그인" 버튼만 본다. 버튼을 누르면 카카오에서 로그인·동의한 뒤 `/`로 돌아와 기존 화면을 보고, 오른쪽 위에 카카오 닉네임과 로그아웃 버튼이 있다. 로그인은 30일 유지되고, 로그아웃하면 로그인 화면으로 돌아간다. 로그인하지 않으면 줄이기·목록 서버 함수가 401로 거절한다. 이 티켓에서 목록은 아직 전체 목록이다. 명세: `.scratch/kakao-login/spec.md`

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] User를 카카오 회원번호로 만들고, 다시 로그인하면 닉네임만 갱신한다
- [x] 세션을 Postgres에 30일 저장하고 HttpOnly·SameSite=Lax 쿠키(https면 Secure)로 준다. 만료된 세션은 로그인 안 한 것으로 본다
- [x] `GET /auth/kakao/login`이 state 쿠키를 심고 카카오 인가 주소로 302
- [x] `GET /auth/kakao/callback`: state가 맞고 code가 있으면 세션 쿠키 + `/`로 302. state 불일치, code 없음(취소), 카카오 실패면 세션 없이 `/`로 302
- [x] `POST /auth/logout`이 세션을 지우고 쿠키를 만료시키고 `/`로 302
- [x] 로그인 전 `/`는 제목과 로그인 버튼만 가운데, 줄이기 폼과 목록 없음. 로그인 후 `/`는 기존 화면 + 오른쪽 위 닉네임과 로그아웃 버튼
- [x] 세션 없이 줄이기·목록 서버 함수를 부르면 401. Follow는 로그인 없이 그대로
- [x] 카카오 클라이언트를 주입받는 경계(인가 코드 → 회원번호·닉네임)를 두고, 실제 구현은 REST API 키 + Client Secret으로 토큰을 받아 사용자 정보를 조회한다
- [x] `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`이 없으면 서버 시작이 실패한다. `render.yaml`에 대시보드 입력값으로 추가
- [x] 배포 문서에 카카오 디벨로퍼스 설정 순서, AGENTS.md에 로컬 환경 변수 안내
- [x] 경계 1 테스트: sign_in, 세션 시작·조회·종료·만료
- [x] 경계 2 테스트(가짜 카카오): 로그인 전 화면, login 302, callback 성공·실패, 로그인 후 화면, 로그아웃, 401, 쿠키 없는 Follow
- [x] 진짜 카카오 키로 로컬에서 로그인 → 닉네임 확인 → 로그아웃을 직접 확인했다
